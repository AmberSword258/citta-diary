## 这是什么

观心 Citta 是一款面向 Windows 的个人日记桌面应用：打开就是当月的日历，点一天写一页，正文用 Markdown，心情、天气、标签随手记。所有日记与图片在本机加密后落盘，应用不联网、不上传、不需要账号，也没有云端同步。

它适合想把写日记当成长期习惯、又不想把私密文字交给第三方服务的人：界面按宣纸与墨色的思路设计，安静、克制，能长期看下去。

## 快速开始

### 方式一：免安装包（普通用户）

1. 解压 `观心 Citta-win-x64` 文件夹（见[打包为免安装应用](#打包为免安装应用)）。
2. 双击其中的 `观心 Citta.exe`。
3. 首次启动会引导你设置**启动密码**与**三个密保问题**，之后每次打开都需要输入密码解锁。

日记数据不会放在程序目录里，而是写入 `%APPDATA%\观心 Citta`，设置面板里的「打开数据目录」可以直接定位到它。

### 方式二：从源码运行

需要先装 [Node.js](https://nodejs.org/)（自带 npm）。本项目唯一的依赖是 Electron（开发依赖），首次安装需要能访问 npm 源。

**最简单：双击项目根目录的 `启动观心.bat`。** 它会在首次运行时自动执行 `npm install`，之后双击即刻打开。

也可以在命令行里启动：

```powershell
npm install   # 仅首次需要
npm start
```

| 命令 | 作用 |
| --- | --- |

| `npm run dev` | 启动应用并带上 `--dev` 参数 |
| `npm test` | 运行全部六组测试（入口 `tests/run.js`） |
| `npm run test:lunar` | 只跑农历 / 节气 / 节日算法（纯 Node，不需要 Electron） |

| `node tools/audit-visual.js` | 视觉规范静态审计：设计令牌、禁止清单、字号下限 |

`npm test` 的六组测试依次是：

1. 农历 / 节气 / 节日算法（纯 Node）
2. Markdown 渲染器（纯 Node）
3. 存储、加密与备份
4. 视觉规范：在真实窗口里读取计算样式、版式几何，并逐项计算浅色与深色两套主题的 WCAG 对比度
5. 内容保真：保存不会损坏原文
6. 端到端界面流程（启动真实 Electron 窗口驱动 UI，并测量 1000 篇日记的载入、列表与搜索耗时）

第 3–6 组需要 Electron 可执行文件（`node_modules/electron/dist/electron.exe`）；若未安装依赖，`npm test` 会跳过这几组并在结果里标注「跳过」。

### 测试跑不起来？先看这个环境变量

如果第 3–6 组全部失败，而第 1、2 组正常，几乎可以肯定是环境变量 `ELECTRON_RUN_AS_NODE` 被设成了 `1`。

它会让 Electron **退化成纯 Node 运行**，此时 `require('electron').app` 是 `undefined`，
报错长这样：

```
TypeError: Cannot read properties of undefined (reading 'setPath')
```

某些工具链（部分 Node 版本管理器、CI 配置、其他 electron 项目）会设置这个变量。
临时清掉即可：

```powershell
# PowerShell（当前会话）
Remove-Item Env:\ELECTRON_RUN_AS_NODE
npm test

# cmd（当前会话）
set ELECTRON_RUN_AS_NODE=
npm test
```

同理，`tools/make-screenshots.cmd` 里也预先清掉了它 ——
否则截图脚本会在第一行就崩掉。


## 打包为免安装应用
```powershell
npm run dist
```

> 注：打包脚本是 `tools/build-portable.js`，零依赖、离线可跑：它复制 `node_modules/electron/dist` 运行时，把应用放进 `resources/app/`，并把 `electron.exe` 改名为 `观心 Citta.exe`。

### 体积

Electron 自带一整套 Chromium，所以**未压缩约 225 MB，压缩后约 62 MB**（zip 约 90 MB）。脚本默认做了两件精简：

- 只保留 `zh-CN` / `en-US` 两种语言包，删掉其余 53 种（省约 **38 MB**）
- 删掉 `vk_swiftshader.dll` / `vulkan-1.dll` 软件渲染兜底（省约 **6 MB**）——如果你的目标机器是没有显卡驱动的虚拟机，用 `node tools/build-portable.js --keep-swiftshader` 保留它们

打包结束会自动用 7z（LZMA2 最高压缩）生成 `dist/观心 Citta-win-x64.1.0.0.7z` 作为发布包；机器上没有 7z 时退回 zip。想跳过压缩用 `--no-pack`。

想再小只能换掉 Electron 外壳（改用系统自带 WebView2，例如 Tauri），那是一次重写，不在本项目的范围内。

打包完成后产出目录 `dist/观心 Citta-win-x64/`，这是一份**免安装（portable）**的文件夹，用户解压后直接双击 `观心 Citta.exe` 即可使用，不需要安装程序、不需要管理员权限。

目录里是两部分：

| 内容 | 说明 |
| --- | --- |
| `观心 Citta.exe` | 应用可执行文件 |
| Electron 运行时 | `*.dll`、`*.pak`、`locales/`、`resources/` 等，随包自带，因此用户机器上不需要预装 Node 或 Electron |
| `resources/app/` | 本项目源码（`src/`、`package.json`、`logo.ico` 等），也就是被运行的应用本体 |

**日记数据不在这个文件夹里。** 无论从源码运行还是用免安装包运行，日记都写在 Electron 的 `userData` 目录 `%APPDATA%\观心 Citta`，所以：

- 打包出来的目录、以及分享给别人的压缩包中，**不含任何个人数据**；
- 升级时用新版本的目录替换旧目录，已有日记不受影响；
- 备份与迁移请用设置面板里的「导出备份」（见[数据与隐私](#数据与隐私)）。

免安装目录就是一份完整的 Electron 运行目录加一份应用代码，因此也可以手工组装：复制 `node_modules/electron/dist/` 为一个新目录，把本项目文件放进其中的 `resources/app/`，再把可执行文件改名为 `观心 Citta.exe` 即可得到同样的结果。

## 数据与隐私

全部数据都位于 Electron 的 `userData` 目录，Windows 下即 `%APPDATA%\观心 Citta`（设置面板里的「打开数据目录」按钮可直接打开它）：

| 文件 / 目录 | 内容 |
| --- | --- |
| `vault.json` | 密钥库：口令与密保的**校验信息**，以及被包裹后的主密钥；不含明文密码，也不含明文答案 |
| `entries.json` | 全部日记密文：每条日记单独加密，各自独立 IV |
| `images/` | 图片密文，每张图片一个 `<id>.bin`，与日记同样加密 |
| `backups/` | 存储层创建的备份目录（导出时可在对话框里另选存放位置） |
| `prefs.json` | 唯一的明文文件：只保存界面偏好（主题：`"light"` / `"dark"` / `"system"`），不含任何日记内容；语言偏好同样只作为界面偏好保存在本机 `userData` 目录中 |

### 加密是怎么做的（大白话）

1. 首次设置密码时，应用随机生成一把**主密钥**；之后每条日记、每张图片都用它做 AES-256-GCM 加密。
2. 主密钥本身不会直接落盘：它被「口令密钥」包裹后存进 `vault.json`，而口令密钥由你的密码经 scrypt（N=16384, r=8, p=1）派生。
3. 因此**修改密码只需重新包裹主密钥**，不需要重新加密全部日记。
4. 三个密保答案各自派生一把密钥，各包裹一份主密钥副本；答对任一题即可解出主密钥。
5. 密钥**只存在于内存**中，锁定应用或退出进程即消失；磁盘上永远只有密文。
6. 单条密文损坏不会连累其它日记，那一天会被单独标记为解密失败。

### 关于备份文件（重要）

> **导出的备份 JSON 是明文的。** 备份里包含全部日记正文与图片，只是为了便于换机迁移而没有加密。

请妥善保管备份文件：不要随意分享，也不要放在公开的云盘链接里。需要长期归档时，建议放在自己可控的加密磁盘或加密压缩包中。

## 技术要点

### 农历与节气：完全自研，零依赖

不使用任何预置农历数据包，而是用天文算法实时推算：

| 环节 | 方法 |
| --- | --- |
| 二十四节气 | **VSOP87D** 地球日心黄经截断级数 + 黄经章动，对太阳视黄经到达 15° 整数倍的时刻做**牛顿迭代**；时刻由 TT 经 **ΔT**（Espenak–Meeus 多项式）换算到北京时间 |
| 月球与朔 | **Meeus《天文算法》第 47 章**月球视黄经 + **第 49 章**朔时刻，再以「日月视黄经差为 0」迭代收敛 |
| 农历编算 | 按 **GB/T 33661-2017《农历的编算和颁行》**：以东八区日界为准，含冬至的朔望月为十一月，其后含中气者依次进月序，不含中气者为闰月 |
| 可靠性兜底 | `src/shared/lunar-table.json` 收录 1901–2100 的权威春节日期（200 条）与闰月表，由 `tools/build-lunar-table.js` 生成并自检，作为主路径保证与官方历书一致 |

验证结果：

| 项目 | 结果 |
| --- | --- |
| 春节日期 | 1901–2030 全量对照权威表 **131/131 正确** |
| 农历年结构 | 1901–2099 **0 异常** |
| 逐月对照 | 2022 年各月与官方万年历 **12/12 吻合** |
| 节气时刻 | 与官方发布吻合到分钟 |

### 加密设计

```
密码 ──scrypt──▶ 口令密钥 ──包裹──▶ ┌──────────┐
                                    │  主密钥  │ ──AES-256-GCM──▶ 全部日记 & 图片
密保答案 ─scrypt─▶ 找回密钥 ──包裹──▶ └──────────┘
```

| 参数 | 值 |
| --- | --- |
| 加密算法 | AES-256-GCM（认证加密），每条数据独立 12 字节 IV，16 字节认证标签 |
| 密钥派生 | scrypt，N=16384、r=8、p=1，派生 32 字节密钥 |
| 主密钥 | 32 字节随机值，仅存在于内存；磁盘上只有被包裹后的密文 |
| 落盘方式 | 先写 `.tmp` 再 `rename` 覆盖，避免写一半损坏；连续保存做 400ms 节流合并 |

| 全文搜索 | <1ms |

端到端测试同时以阈值把关同一组操作：载入 <2500ms、列表 <1500ms、搜索 <200ms。

### 渲染层加固

- 渲染层开启 `contextIsolation`、关闭 `nodeIntegration`，并通过 **CSP** 限制资源来源：`default-src 'self'; img-src 'self' data: citta-img:; style-src 'self' 'unsafe-inline'; script-src 'self'`。
- 渲染层拿不到 Node、拿不到密钥，也无法直接读写文件；所有数据访问必须经过 `preload.js` 暴露的最小 API 走 IPC，主进程用统一包装把异常转成错误信息（不把堆栈抛给界面）。
- Markdown 渲染输出的所有 HTML 都转义，只输出白名单标签；链接只允许 `http` / `https` / `mailto`，图片只允许 `data:image/*` 与本地的 `citta-img://<32 位十六进制 id>`。
- 外部链接一律交给系统浏览器打开，应用内不做导航。
- 农历计算在主进程完成，渲染层只接收算好的纯数据。

## 已知边界
- 农历的**权威兜底表覆盖 1901–2100**；超出这个范围的日期不在保证之列（应用定位是个人日记，日常使用不受影响）。
- **备份文件是明文**：这是为跨设备迁移做的取舍，请妥善保管，不要分享。
- **exe 文件图标**仍是 Electron 的默认图标（窗口图标与任务栏图标是观心的 logo）。改 PE 资源需要额外工具。
- **发布包约 62.5 MB**：体积来自 Electron 自带的 Chromium 运行时，与应用代码无关（应用本身 2.2 MB）。想降到 10 MB 以内需要换掉外壳，评估见 [`docs/MIGRATION-TAURI.md`](docs/MIGRATION-TAURI.md)。
- **English 模式下，农历、节气、节日的文字仍为中文**——它们是中文历法数据，刻意不翻译（`i18n` 只翻译界面文字，用户写下的正文、标签、大事、搜索片段永不翻译）。
- 目前只有 Windows 版；没有云端同步、多设备协同或手机端，数据只在本机。

## 已知问题

以下问题由项目自带的测试发现，**目前保留未修**，一并公开记录：

### 视觉规范：月历日期对比度未达项目自定标准

测试 `tests/visual.test.js` 会在真实窗口里逐项计算 WCAG 对比度，
它把「正文 / 月历日期 / 月标题 / 条目正文」等归为**必读文字，要求 ≥ 7**（AAA 级），
次要文字要求 ≥ 4.5。

实测结果：

| 元素 | 实测 | 项目标准 | 结果 |
| --- | --- | --- | --- |
| 月历日期（浅色） | 5.7 | ≥ 7 | 未达标 |
| 月历日期（深色） | 5.95 | ≥ 7 | 未达标 |
| 深色·平日日期 | 5.95 | ≥ 7 | 未达标 |

需要说明的是：**5.7 已满足 WCAG AA 的 4.5**（正常字号），
只是没达到项目给自己定的 AAA 更高标准。字色偏浅是「宣纸与墨色」这套设计语言的一部分，
调深会改变整体观感，因此没有擅自改动。

### 英文界面：农历节日名未翻译

切到英文后，农历节日名（如「国庆节」）仍显示中文。
其余界面文字均已翻译，`tests/e2e.js` 会检查 `CittaI18n.untranslated()` 是否为空，
因此这一条会让端到端测试报 1 处失败。

这条与上面「已知边界」里提到的设计取舍是同一个问题：
农历 / 节气 / 节日属于中文历法数据。目前的做法是界面文字全译、历法数据保持中文，
但节日名恰好走了界面的渲染路径，于是被漏译检查抓了出来。
要么把它们也纳入翻译表，要么在检查里显式豁免 —— 尚未决定。

### CI 是怎么处理的

`.github/workflows/ci.yml` 里：

- **门禁**：纯 Node 的两组测试（农历算法、Markdown）必须通过，否则 CI 失败
- **报告**：完整六组套件照常运行并输出日志，但当前**不参与失败判定**

这样真实的回归会被立刻抓到，同时上面两个已知问题不会让 CI 长期变红。
等它们修掉之后，把「Run full suite」那一步的 `continue-on-error` 去掉即可升级为门禁。
